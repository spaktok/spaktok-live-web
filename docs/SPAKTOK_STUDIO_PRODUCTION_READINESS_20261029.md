## What the existing code actually provides

- `spaktok-forge.tsx` offers local 2.5D relief with no GPU and an opt-in paid 360 image-to-GLB path.
- `spaktok-ai-director.ts` routes requests into private drafts for Avatar, Live, Filter, Gift and World. It is a deterministic text router, **not autonomous LLM orchestration**.
- `spaktok-studio-fanout.ts` creates separate destination profiles with explicit **rigging, animations, scale, camera and Android QA blockers**. It does not silently publish.
- `/api/spaktok-forge/gpu-ticket` issues signed, limited, one-use creator requests after auth, rights and compute/transfer consent; it cannot itself compute a model.
- The optional GPU server supports `stable-fast-3d` and `trellis2` (the latter wired, not end-to-end proved).
- `spaktok-forge-readiness.ts` now carries explicit disabled / pending-model-access / unverified / offline / ready statuses. The API does **not** issue paid tickets when `SPAKTOK_FORGE_GPU_MODEL_ACCESS` is not exactly `approved`.
- The operator's temporary `trycloudflare.com` portal and terminal URLs **must never be used as the model API**.

The `SPAKTOK_FORGE_GPU_MODEL_ACCESS` flag is the **operator's attestation**, not proof of license approval. Do not set `approved` just to bypass a failing model download. The server's HMAC health check must also succeed. The API remains disabled unless *both* feature flags are true.

## Professional multi-service target (NOT yet implemented as production workflow)

```text
Spaktok AI request and rights confirmation
  -> Studio Orchestrator [authenticated job, per-user quota, cost policy]
  -> D1 durable job metadata (pending/running/failed/completed/reviewed)
  -> Cloudflare Queue or Workflow [retry policy, failure handling]
  -> Dedicated private GPU worker (TRELLIS.2 / future approved model)
  -> Private R2 model asset (GLB master, hash, source provenance, preview)
  -> Geometry/PBR and privacy QA, mesh optimization + LODs
  -> Private review in Studio
  -> Fan-out profiles:
      Avatar: facial/body rig and animation evaluation
      Live: tracking/Agora latency, performance and gift rules
      Filters: anchors, occlusion, tracking, thermal limits
      Gifts: animation, FX, attribution, monetization review
      World: scale, collision meshes, LODs and streaming budgets
  -> Publish ONLY after explicit human approval and mobile tests
```

A fast 3D model alone does not rig faces, generate stable gesture animations, or guarantee a 360 reconstruction from one image. Cross-team fan-out is **metadata/planning** until adapters perform real transformations.

## Production gaps / non-negotiable release gates

- **No permanent quick tunnel or shared Jupyter URL in production**; use a stable locked-down provider API, ideally Cloudflare Tunnel + Access, with real zero-trust authentication, rate limits and origin pinning.
- **No persistent job queue yet**, no cross-worker durable replay store, no autoscaling, no GPU rental automatic termination, no guaranteed D1/R2 model registry.
- Use immutable model and CUDA image versions, model-card license audits, signed/hardened image sources and rollback on model crashes.
- Protect user photos/3D likenesses. Define retention/deletion policy, encrypted storage, private access, consent, and abuse safeguards before allowing external creators.
- Build benchmarking on the *same original input* and same target output complexity against Rodin, using geometry quality, PBR texture quality, backside coherence, rigging, mobile framerate, failure rate, actual cost/asset, blinded ratings and reference samples. Do not claim Spaktok is superior without evidence.
- GitHub Actions on this feature branch currently reports **failure**. Do not merge or deploy the branch before checks pass and a real one-asset end-to-end proof is captured.
